This additive gate qualifies the intended Defaults `7b3099bf` / Contracts `99529ad6` graph before the existing PO proof. Source preparation and pure rejection controls do not establish native acceptance. `candidate-pins.json` remains `acceptedProducerGraph=false`; admission requires the actual own-run graph receipt and fresh standalone binary joins.

The expected inventory records original source identity and case multiplicity only. Every producer preserves Release warning/error refusal, full formatting, complete package audit, the existing pinned redacted Gitleaks/JWT/current-tree scanners and raw generated-inclusive coverage. Document preserves its existing contract-only Application policy: pristine PE/PDB capture, original five compiled mutations, twenty metadata controls, 43 actual HTTP rows, same-source/run/attempt policy reinspection, and explicitly false numerical/four-assembly acceptance. Employee's original scaffold orchestration controls also run.

These test-only sources never replace the PO application checkout. The consumer's canonical Git SHA256 `98a4b295...` and CRLF checkout SHA256 `a4a31a99...` are independently checked according to its immutable `.gitattributes`. Strict scan sources are the original `dotnet-validate` action's Workflows `e3a60933` tree and Gitleaks commit `6eaad039`.

The observer admits an actual unfiltered Docker HTTP event stream before producer command dispatch. It retains bounded periodic unfiltered history replay with an actual previous boundary-event anchor, initial-prefix proof, exact nanosecond interval comparison and a raw interval capacity refusal. A timer alone is not a continuity proof. Lost anchors, gaps, overflow, unknown actors, failed daemon reads or missing original inspect generation stop admission. Docker daemon identity includes ID, PID/birth, executable and socket inode; each census checks the generation before and after successful full inventories.

Original full container IDs, immutable image identities, creation/terminal times and original inspect labels are retained. Anonymous volumes require actual original container mount attribution. Frozen original fixtures create no custom network. Expected image cache pulls remain a declared cache boundary; no daemon objects are adopted, deleted or pruned. Every created resource requires a terminal event and a fresh successful same-daemon census proving its exact original ID absent. Both retained observer/fencer threads and original command process sessions must settle before the next producer or business stage.

The Testcontainers session UUID is an SDK process-context label, not an OS PID/session binding. SDK4.10 uses `postgres:18-alpine` and default `testcontainers/ryuk:0.14.0`. Ryuk retains the nonzero session-id label but overrides its resource-reaper-session label to the empty UUID; normal Postgres retains the default cleanup UUID. These facts are bound to the [original SDK label source](https://github.com/testcontainers/testcontainers-dotnet/blob/4.10.0/src/Testcontainers/Clients/DefaultLabels.cs), [reaper source](https://github.com/testcontainers/testcontainers-dotnet/blob/4.10.0/src/Testcontainers/Containers/ResourceReaper.cs) and [builder source](https://github.com/testcontainers/testcontainers-dotnet/blob/4.10.0/src/Testcontainers/Builders/AbstractBuilder%604.cs).

The bounded graph claim is native completion of unchanged original fixtures, observed exact born-resource absence, and supervised process/session closure. Docker events do not certify individual Testcontainers SDK-object Dispose calls. Unknown identity or an escaped/unsettled session cannot qualify. PO's separate original 51-client/two-backend INIT/signature/provider/quiescence/exact-SDK-absence/release gates remain unchanged.

Failure cleanup retains the original failure separately from cleanup results. Surviving original session children are signaled only after PID/birth/session/executable checks and pidfd admission; a changed generation is refused. Phase revisits share the original 30-second process-settlement deadline. Failed observer admission closes its retained original socket, joins its original reader, obtains a final census and writes an explicitly incomplete receipt before raising. Unknown/unsettled readers or processes remain failures even if later cleanup succeeds; no other daemon object or process is adopted.

After standalone Release build, admission reparses the actual private raw TRX, raw coverage, asset/project paths, audit/log hashes and original compiled-policy receipt, then compares every consumed producer/shared DLL/PDB against the pristine observed binary graph. The final PO retainer independently repeats the graph/binary conjunction alongside every original business/native/cleanup gate. Raw TRX, logs, private test configuration, PDFs and compiled policy inputs remain under RUNNER_TEMP; public artifacts project sanitized source/native/hash/coverage/process/resource receipts only. An incomplete graph never becomes a business pass.
