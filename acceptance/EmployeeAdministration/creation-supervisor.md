# Creation supervisor preparation

This standalone Python supervisor has source compilation and focused ownership-control tests. Its source CI does not start Docker, SDK processes, or application hosts.

The creation application graph is not included in this slice. Before native use, Root must qualify and seal the consumer CreationMode source and actual Auth, Employee, Country, ServiceDefaults, and CompatibilityContracts dependencies. Employee main bb7333 does not contain the optional-address source packet. Existing six-case application CI and its pins are unchanged.

Native invocation requires a dedicated GitHub-hosted Linux runner, Root sole-lane admission, at least 4096 MiB available memory, systemd/cgroup v2, and reviewed tmpfs-only PostgreSQL/Redis fixtures. The supervisor creates a private daemon socket/config/data root and an owned bridge and slice. It caps the aggregate slice at 3840 MiB, each SDK phase at 2048 MiB, and the daemon at 512 MiB. Actual container init cgroups must be beneath that slice. Units carry a finite lease and observed process IDs/start times.

Cleanup first verifies SDK quiescence, then verifies exact container IDs, owner labels, tmpfs-only mounts, loopback forwarding and absence of active clients. It never removes volumes. Foreign or uncertain resources are preserved with ownership evidence; they do not count as cleanup success. Raw native logs and TRX stay private.

Native success, cancellation, partial host startup, PID/cgroup cleanup and full application build/test coverage remain unqualified. A source-controls green run is not employee creation execution proof or genuine IAM enrollment proof. Runtime should remain opt-in until those checks are complete.
The CLI additionally requires an explicit reviewed source-seal JSON and its SHA-256. It verifies the source hashes before creating native resources and again after tests. The seal must cover the consumer and every dependency root and compile the creation symbol.

The independent creation parser requires all 22 cases: existing six, creation seven, and admission/cleanup nine. It rejects an old six-case report, skipped or duplicate cases, mismatched definitions and false counters. Its synthetic parser controls are never classified as native execution. A sanitized native proof is written only after actual TRX validation and successful ownership cleanup.

V2 keeps a durable unit name, executable, command digest and unpredictable description fence before dispatch. The same owner reacquires partially started units after a failed control call, checks their generation and cgroup, and performs cleanup. A foreign fence remains quarantined and never counts as release.

Before the first SDK allocation, the private socket must be a nonlinked Unix socket whose kernel inode appears among the observed dockerd process's descriptors. The exact daemon command digest and its owned cgroup parent are checked.

Control output is read without worker threads, limited to 256 KiB, with actual owned-child exit and reader closure on timeout or overflow. Native stdout uses an owned FIFO and an 8 MiB per-phase private-log budget; overflow invalidates execution proof.

The recovery and socket checks still require actual hosted runtime qualification. Unit models and three actual tiny Python control-child executions are standalone supervisor checks, not application-host execution.

V3 handles terminal units through their immutable unit generation and an empty owned cgroup; historical ExecMainPID values are never treated as live ownership. Each FIFO drain is bounded to eight reads per stream and ten milliseconds per call. Slice creation atomically applies a nonce description and resource limits through StartTransientUnit. Bridge creation atomically applies a nonce alias. Durable intent precedes both dispatches, allowing exact-fence recovery after a control timeout. Unresolved or changed ownership fails cleanup and preserves evidence. Actual Linux dispatch, cancellation and runtime cleanup remain unqualified.

V4 retains the exact Popen child handle and pipe reader when termination, killing, waiting, or identity observation fails. A same-owner reaping barrier runs before every native command and before cleanup snapshots; unresolved control processes prohibit native cleanup. Process birth and actual executable identity are recorded when observable. FIFO descriptors are registered before opening their log files. Ownership receipts flush and fsync their contents, preserve the prior inode, atomically replace the current receipt, and fsync the containing directory on Linux. Windows source controls model directory synchronization and do not qualify Linux crash durability. Actual hosted failed-reap recovery remains unqualified.

V5 keeps the same supervisor in cleanup-only recovery while any retained helper is live or unknown, including after the native lease expires. It does not renew native work and cannot return from execute-finally until helper settlement permits cleanup. Receipt-disk failure does not discard in-memory handles. Native invocation additionally requires an externally created transient control service under `/system.slice/codex-creation-supervisor-<32 lowercase hex>.service`, with `MALIEV_CREATION_CONTROL_UNIT` identifying that unit and `MALIEV_CREATION_CONTROL_FENCE` carrying a fresh 32-hex description nonce. Its description must be `CodexCreationControl:<nonce>`; actual main PID, executable, generation and cgroup must match this supervisor. RuntimeMaxSec must be finite and at most 26 minutes, TimeoutStopSec at most 20 seconds, KillMode control-group, SendSIGKILL yes, Delegate no, and MemoryMax at most 128 MiB. Typed DBus microsecond properties enforce the lease; native work reserves its final two minutes for cleanup. Every control child must inherit this exact cgroup. An external lease kill is not a successful release receipt: the bootstrap owner must verify the control cgroup and retained native resources separately. The required native bootstrap and actual systemd expiry remain unqualified and are not provided by the source-only workflow.

Typed property parsing uses busctl get-property scalar JSON, verified against the primary [systemd busctl](https://github.com/systemd/systemd/blob/main/src/busctl/busctl.c) and [JSON transformer](https://github.com/systemd/systemd/blob/main/src/libsystemd/sd-bus/bus-dump-json.c) implementations. Native Linux compatibility remains pending actual execution.

V6 keeps the recovery loop around every cleanup attempt, including manager, Docker and stop helpers created during cleanup. A failed attempt remains sticky and never becomes a native proof after later settlement. Child ownership registration now precedes executable lookup or path resolution immediately after Popen returns.

`bootstrap_creation_join.py` provides the source for the finite control-service launch: it persists the unique unit/fence before dispatch, observes actual generation/executable/process identity and cgroup, and preserves this same owner when its own final observations create an unreaped helper. Terminal/expired services require an empty control cgroup and matching native ownership receipt, empty native slice, absent owned bridge, settled native controls, and absent disposable daemon directories. Unavailable receipts and remaining resources fail closed. It never removes persistent volumes or globally stops resources. Source-only CI compiles this bootstrap and exercises its controls; it does not invoke it. Actual bootstrap startup, cgroup inheritance, systemd expiry, sudo-child containment, service cancellation and partial dispatch remain native qualification requirements.

The first actual hosted control smoke failed closed when the unprivileged runner could not read an elevated helper process identity. Native bootstrap/controller entrypoints therefore require root in their dedicated ephemeral hosted runner; sudo preserves only explicit hosted admission variables for the smoke. Control receipts identify their failure stage. Root mode does not qualify lifecycle behavior by itself and does not remove the finite-unit and ownership gates.
